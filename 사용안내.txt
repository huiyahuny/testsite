캐릭터 · 세계관 아카이브 — GitHub 관리자 편집기 버전
========================================================

[1] 바뀐 내용
- 방문자 페이지의 검정/금색 디자인은 기존과 동일합니다.
- 메인 페이지 하단 오른쪽의 ADMIN 링크를 누르면 admin.html로 이동합니다.
- admin.html에서 고정 인증값을 입력하면 편집 화면이 열립니다.
- HOME/공통, WORLD, CHARACTERS, TIMELINE, ARCHIVE를 사이트에서 직접 수정합니다.
- 항목 추가/삭제/위아래 순서 변경을 지원합니다.
- 캐릭터 이미지는 PNG/JPG/WEBP 파일 선택 후 미리 볼 수 있습니다.
- GitHub 저장 버튼을 누르면 저장소의 data.js를 수정하고 이미지를 images/에 업로드합니다.

[2] 먼저 바꿀 파일 — admin-config.js

window.ARCHIVE_ADMIN_CONFIG = {
  editorCode: "[이곳에 관리자 인증 값을 입력하시오]",
  owner: "huiyahuny",
  repo: "testsite",
  branch: "main"
};

아래 부분만 따옴표를 남기고 원하는 문자열로 변경합니다.

  editorCode: "[이곳에 관리자 인증 값을 입력하시오]"

예)
  editorCode: "my-archive-code-2026"

★ 주의: GitHub 저장소가 Public이므로 이 고정 문자열은 공개 소스에서 누구나 확인할 수 있습니다.
★ 따라서 이 값은 안전한 '관리자 인증'이 아니라 단순한 편집 화면 열기용 잠금입니다.
★ 기존 비밀번호, 이메일 계정 비밀번호, GitHub 로그인 비밀번호 등을 넣지 마세요.
★ 실제 GitHub 파일 수정 권한은 반드시 GitHub Personal Access Token(PAT)으로 제어합니다.

[3] 기존 GitHub 저장소에 업로드
1. 이 ZIP을 압축 해제합니다.
2. 아래 8개 파일을 전부 선택해 저장소의 'main' 브랜치 최상위에 업로드합니다.
   - index.html
   - style.css
   - app.js
   - data.js
   - admin.html
   - admin.css
   - admin.js
   - admin-config.js
3. 기존 4개는 같은 파일명으로 교체되고, 관리자 파일 4개는 추가됩니다.
4. Commit changes를 선택합니다.
5. GitHub Pages 배포 완료 후 주소로 접속합니다.
   방문자: https://huiyahuny.github.io/testsite/
   관리자: https://huiyahuny.github.io/testsite/admin.html

파일을 올리기 편한 직접 업로드 주소:
https://github.com/huiyahuny/testsite/upload/main

선택 파일: .nojekyll (필수 아님)
폴더 images는 빈 상태일 때 GitHub 화면에 보이지 않을 수 있습니다. 첫 이미지 업로드 때 자동 생성됩니다.

[4] GitHub 토큰 만들기 (실제 콘텐츠 자동 저장에 필요)
1. GitHub 로그인 → https://github.com/settings/personal-access-tokens/new
2. Fine-grained personal access token 생성
3. Resource owner = 본인 계정
4. Repository access = Only select repositories → testsite
5. Repository permissions → Contents → Read and write
6. Expiration은 필요 기간만큼 짧게 지정하는 것을 권장합니다.
7. 생성된 토큰은 안전한 곳에 보관합니다. 공개 저장소/소스/채팅에 붙이지 마세요.

[5] 사이트에서 편집하기
1. https://huiyahuny.github.io/testsite/admin.html 열기
2. admin-config.js에 직접 설정한 인증값을 입력합니다.
3. HOME/세계관/캐릭터/연대기/자료실에서 글과 이미지를 수정합니다.
4. 가장 아래 [GitHub 액세스 토큰]에 토큰 입력 → [저장소 연결 확인]
5. [수정 내용 GitHub에 저장] 클릭
6. GitHub Pages 배포 후 방문자 홈페이지 새로고침

토큰은 세션 중 이 브라우저 탭의 메모리에만 보관되며, 입력칸은 확인 후 비워집니다.
페이지를 새로 열면 토큰을 다시 입력해야 합니다.

[6] 이미지 관련
- PNG/JPG/WEBP 최대 12MB, 캔버스에서 WEBP 변환 및 긴 변 1600픽셀 이내로 축소.
- 저장하면 새 파일이 images/ 디렉터리 안에 추가됩니다.
- 이미지 '제거'는 웹페이지에서 참조만 끊는 기능입니다. 예전 원본은 GitHub 저장소에 남습니다.
- 저장 중 문제가 생기면 이미지 일부만 GitHub에 올라가고 데이터 저장이 실패할 수도 있습니다.
  이때 홈페이지에 반영되지는 않았을 수 있으니 먼저 저장소 상태를 확인하세요.
- GIF 애니메이션, SVG는 업로드 지원 대상이 아닙니다.

[7] 주의사항
- 공개 GitHub Pages이므로 게시 데이터 및 등록한 이미지는 누구나 볼 수 있습니다.
- HTML에서 입력한 값은 GitHub에 저장하기 전에는 방문자 사이트에 반영되지 않습니다.
- GitHub 저장 버튼을 누르지 않은 상태에서 페이지를 닫으면 내용이 유실됩니다.
- 사이트의 고정 인증값만으로 GitHub를 직접 수정할 수는 없습니다. PAT가 필요합니다.
- GitHub API의 파일 충돌이나 네트워크 오류가 발생하면 오류 내용을 표시합니다.
- 토큰을 유출했을 경우 GitHub의 토큰 관리 화면에서 즉시 폐기하세요.
- admin.html 파일이나 인증값을 숨긴다고 보안이 확보되지는 않습니다.

[8] 테스트
- JavaScript 구문 검사 통과
- 관리자 설정값이 비어 있을 때의 차단, 잘못된 값 거부, 올바른 값의 편집 화면 전환 검사 통과
- 캐릭터 추가, 세부항목 추가, 순서변경 검사 통과
- GitHub API 모의 응답을 통한 data.js 자동 갱신 요청 검사 통과
- 이미지 미리보기 및 모바일 가로 넘침 검사 통과
- 실제 사용자의 GitHub 저장소에 연결해 쓰기를 실행하지는 않았습니다.
